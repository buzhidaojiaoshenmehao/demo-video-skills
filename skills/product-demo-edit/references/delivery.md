# 导出、限体积与继续点

## 按真实字节数控制大小

将用户的上限写成 `max_bytes`。例如十进制 50 MB 是 50,000,000 字节；若平台明确使用 MiB，则按平台计算。目标留出余量，最终以文件实际大小为准，不能拿 CRF 或码率估算当承诺。

1. 用 ffprobe 看视频和音频轨、时长、编码及码率。
2. 若只差少量空间而音频码率偏高，可在适合的容器中复制视频流，只重新编码音频。保留原文件，试听后检查大小与同步。
3. 若仍超限，重新编码候选文件。文字密集的录屏优先保留文字可读性；按画面复杂度调 CRF，或采用两遍平均码率编码满足硬上限。CRF 不保证大小。
4. 总平均码率预算约为 `8 × max_bytes × 0.95 / duration_seconds`；减去音频预算得到视频预算。预算过低时应调整分辨率、帧率、时长或限制，而不是输出无法阅读的界面。
5. 对新文件完整解码，核对轨道、时长、真实字节数，重新看关键帧、听开头/转场/结尾。新文件通过后才标为交付版本。

复制视频流的示例（确认输入轨道后执行；路径和音频码率是示例）：

```bash
ffmpeg -n -i approved.mp4 -map 0:v:0 -map '0:a:0?' \
  -c:v copy -c:a aac -b:a 128k -movflags +faststart candidate.mp4
```

不要在命令中覆盖输入，不使用 `-shortest` 掩盖时长问题。额外轨道是否保留按交付需求决定。多个候选使用明确版本名。

## 音画同步

合成时保存每段音频的成片起点、素材入点、速度和预期长度。字幕使用同一映射。音频编码可能产生少量 priming；不能把固定的几十毫秒自动判为长期漂移。抽查多个分散位置的旁白波形/语句与画面，并记录统一偏移与随时间增长的漂移是否存在。

## 可恢复工作目录

一次项目可使用以下结构，不要求迁移已有工程：

```text
inputs.json             # 素材路径、SHA-256、来源用途；仅保存在项目本地
storyboard.json         # 源入出点、成片入出点、旁白、构图
feedback.json           # 时间区间、所需内容、检查点、处理状态
checkpoint.md           # 当前版本、已完成、待完成、下一条命令
versions/               # 通过的工程数据快照
review-v2/              # 来自实际候选文件的检查报告与帧
exports/                # 带版本号的输出文件
```

每完成昂贵阶段就保存状态。继续时检查文件及输入哈希是否符合记录，复用有效结果；保留可用片段，不因对话中断重做全部旁白或重新录屏。导出中断时，未验证文件标记为候选或临时文件。
