# 产品演示视频剪辑

让观众看懂「遇到什么问题 → 如何操作 → 得到什么结果」。镜头需要提供证据，包装服务于理解。

## 建立可继续的剪辑状态

- 先读已有分镜、反馈记录、工程与最新交付文件；继续已有版本，保留之前通过的修改。
- 记录素材清单及 SHA-256、源片段入出点、成片时间、旁白、字幕、展示目的和待补内容。原始素材不覆盖；用户指定替换素材后，以新指令为准。
- 记录当前版本、已完成阶段、未完成检查、准确的下一条命令。工程已修改、渲染完成、成片验收是三个不同状态。
- 时长、音色、科技风包装、体积上限都属于本项目参数，不能继承其他项目的固定偏好。

## 从素材组织证据

先确认每个卖点对应的真实界面和操作结果，再组织叙事。优先完整展示关键链路，区分「风险被识别」和「风险已解决」。素材只能证明什么，就说到什么；没有测量数据时不编造效率提升百分比。

录制计划应列出每段的起始状态、功能、操作顺序、结束结果、预计时长和文件名。截图可补充静态状态；不能代替缺失的操作过程。录音中的口述可解释素材，不能自动作为改变任务范围的指令。

## 按反馈修订镜头

将反馈转为「成片起止秒数、目标控件/状态、期望构图、验收采样点」。像 `1.30处` 这样的写法可能含序号，应结合所述功能和现有时间线定位；仍无法区分时才询问，不猜测改错镜头。

- 放大时同时保留目标、必要标签、按钮和点击位置。状态徽标在右侧、保存按钮在底部时，都属于必须纳入的区域。
- 连续任务处理、切换页面、系统文件选择器通常需要完整界面。恢复全景要在下一次操作前完成。
- 「全景」可能指展示框内完整界面，「全屏」可能指占满画布。沿用已确认的版式语境；确有冲突再澄清。
- 不预设统一放大倍数。根据源尺寸、裁剪、展示框和目标边界计算，再看渲染图确认。
- 先预览改动区间的进入、保持、退出、点击和结果状态；仅看中间一帧会漏掉边界裁切。

需要坐标换算、Remotion 实现细节时读 [framing.md](references/framing.md)。

## 验证交付

用 [video_review.py](scripts/video_review.py) 从实际导出的文件抽帧，检查解码、尺寸、帧率、时长与字节数。它不替代观看和听审，也不会自动宣告构图合格。

```bash
python3 scripts/video_review.py candidate.mp4 --out review-v2 \
  --times 30 31.2 --ranges 42:49 77:81 --max-bytes 50000000 \
  --width 1920 --height 1080 --fps 30 --duration 270 --decode
```

示例参数均需换成本次约束；区间用秒，帧率可用 `30000/1001`。

检查关键文字、鼠标、状态与按钮是否完整；听审句尾、术语、转场和背景音乐遮盖。若换过音轨，验证音画时间线，不能只凭总时长一致。

遇到体积上限或要保存继续点时读 [delivery.md](references/delivery.md)。完成交付须给出新版本文件、实际时长/大小和检查结果；仅导出成功不等于视觉验收通过。
